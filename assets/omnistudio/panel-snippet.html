1. OmniStudio Platform Overview

OmniStudio (formerly Vlocity Digital Interaction Platform) combines declarative tools to build customer-centric UIs, guided workflows, and data integration on Salesforce — without heavy custom code.

Three apps working together Cards (FlexCards) show context and actions; OmniScripts guide users through processes; DataRaptors read, transform, and write data. Integration Procedures orchestrate multi-step logic including external calls.

Typical Flow

FlexCard (context)
→
Launch OmniScript
→
DR Extract (prefill)
→
User input
→
DR Load / IP
→
Return to Card

Example: an agent views an Orders card, clicks New Order, an OmniScript launches, a DataRaptor Extract loads products, the agent selects items, and on completion the script returns to the card view.

3. OmniScript Data JSON & Merge Fields

All runtime data lives in an intermediate structure called Data JSON — visible to developers in Preview/Debug, not to end users.

Merge field syntax Access nodes with %NodeName%. Nested: %Parent:Child%. Use in Set Values, action properties, Default Values (LWC), and formulas.

Set Values Action

Use Set Values to rename nodes, populate future elements, concatenate strings, and evaluate formulas:

TaskElement NameValue (fx)
Rename nodeNewName%OldName%
ConcatenateFullName%FirstName% + " " + %LastName%
FormulaNetIncome%GrossIncome% - 5000
Data types must match when populating elements — you cannot Set Values a Text element from a Number element.

Send / Response Transformations

Actions and Integration Procedures trim or reparent JSON before/after execution:

PropertyPurposeExample
Send JSON PathDrill into input nodeContactDetails
Send JSON NodeReparent input under new nameInput or node1:node2
Response JSON PathTrim output to pathAccount
Response JSON NodeReparent output; use for prefillMatch OmniScript element name
VlocityNoRootNodeRemove parent wrapper (OS only)Flatten {path:{a:b}} → {a:b}
List indexResponse JSON NodeListNode|%item% — pipe + merge field for list item

  2. User edits data in the script

5. DataRaptor Formulas

All DataRaptor types support formulas on the Formulas tab. Map formula results to output JSON (Extract/Transform) or sObject fields (Load).

Create a Formula — Steps

  1. Open DataRaptor → Formulas tab → Add Formula
  2. Enter logic, e.g. SUM(Products:Price)
  3. Set Formula Result Path (intermediate node)
  4. Map result on Output / Transforms / Fields tab to final destination

Syntax Rules

  • Reference attributes with @Code — e.g. Account:@GoldStarAccount == "On"
  • Paths use colons: Contact:LastName
  • Variables with spaces: var:"Primary Guardian"
  • List index in mappings: Nephews|1, Nephews|2

Common DR Functions

FunctionUse
SUM, AVG, MIN, MAXAggregations on lists
IFConditional field values (e.g. age > 18 → Authorized = true)
LIST, LISTMERGE, LISTSIZE, SORTBY, FILTERList transforms
QUERY, COUNTQUERYDynamic queries in formulas
Load example Input ContactDetails.Birthdate → formula checks if over 18 → maps @IsAdult to custom Authorized__c checkbox on Contact.

7. Integration Procedures (IP)

An Integration Procedure is a headless, sequential pipeline of actions — ideal when you need multiple steps, external APIs, error handling, or both read and write operations.

Common IP Actions

ActionPurpose
Set ValuesSet or compute JSON values
DataRaptor Extract / Post / Transform / TurboSame as OmniScript DR actions
HTTP ActionREST/SOAP callouts (Named Credential, Apex REST, Web)
Remote ActionInvoke Apex class method
Integration Procedure ActionCall child IP (sync, future, chainable)
Response ActionReturn data to caller
Email, Delete, Matrix, List Merge, IntelligenceSpecialized operations

IP Blocks

  • Conditional Block — run steps when formula is true
  • Loop Block — iterate arrays
  • Try-Catch Block — error handling; returns { "success": false } on failure
  • Cache Block — cache subset of steps for performance

Common IP Action Properties

PropertyDescription
Send JSON Path / NodeTrim/reparent input before action runs
Response JSON Path / NodeTrim/reparent output after action
Additional InputExtra key/value pairs (merge fields, formulas)
Send Only Additional InputIgnore full Data JSON; send only Additional Input
Fail on Step ErrorStops IP if action fails

DR Post in IP returns nodes like Contact_1 with UpsertSuccess. Reference IDs with merge fields: %CreateContact:Contact_1:Id%.

8. Call DataRaptor from OmniScript

OmniScripts integrate with Salesforce through DataRaptor Action elements. Create the DataRaptor first (non-LWC), or use Create New DataRaptor inline in LWC Designer.

DataRaptor Extract Action — Prefill / Read

  1. Build Extract: add extract steps, filters (e.g. Id = %ContextId%), Output mappings — output node names must match OmniScript element names
  2. Drag DataRaptor Extract Action into structure (typically before or in first Step)
  3. Set DataRaptor Interface to your Extract name
  4. Map Data Source → DR input parameter; Filter Value → merge field value
  5. Use Response Transformations to trim/rename if needed
  6. Preview — elements prefilled from response
PropertyDescription
DataRaptor InterfaceName of Extract
Data SourceJSON node supplying filter input
Filter ValueValue matched against sObject field
Response JSON Path / NodeTarget prefill structure
Prefill tip Copy OmniScript Data JSON into DataRaptor Expected JSON Output pane to auto-populate valid output fields. For hidden conditional elements, set "accessibleInFutureSteps": true or check Available for Prefill When Hidden.

DataRaptor Post Action — Write to Salesforce

  1. Build Load: map OmniScript output JSON nodes → sObject fields; set upsert keys
  2. Preview OmniScript → copy Data JSON → paste into DR Input JSON for mapping
  3. Drag DataRaptor Post Action (usually near end of script)
  4. Select Load in DataRaptor Interface
  5. Use Send Transformations so input matches Load structure

DataRaptor Transform Action

Restructure data mid-script without SF I/O — e.g. prepare DocuSign/PDF payload. Select Transform interface; trim input/output with Send/Response properties.

DataRaptor Turbo Action

Single-object fast read. Set Response JSON Path ObjectName|1; optional Response JSON Node = VlocityNoRootNode.

Prefill Repeatable Blocks

Return array whose root name matches block name:

"EditBlock1": [
  { "FirstName": "John", "LastName": "Smith" },
  { "FirstName": "Jane", "LastName": "Smith" }
]

9. Call Integration Procedure from OmniScript

Use when one DR is not enough — multiple reads/writes, HTTP callouts, loops, or error handling.

Steps

  1. Create and activate Integration Procedure (Type_Subtype)
  2. Drag Integration Procedure Action into OmniScript
  3. Select procedure in Integration Procedure field
  4. Configure Send/Response transformations:
    • Send JSON Path — node sent as IP input
    • Send JSON Node — rename input parameter
    • Response JSON Path — trim IP output
    • Response JSON Node — name for subsequent elements
  5. Extra Payload — additional key/value input (merge fields)
  6. Set async options if needed (see table below)
PropertyWhen to Use
Invoke Mode: DefaultBlocks UI with spinner; waits for response
Non-BlockingRuns async; applies response when complete; continues user interaction
Fire and ForgetAsync, no UI callback (debug console only)
Use FutureIP runs as Salesforce future method; no data returned
Is ChainableEnable child IP chainable settings
Use ContinuationLong-running callouts via Apex continuations
Send Only Extra PayloadSend only Extra Payload, not full Data JSON
Multiple posts? Host several DataRaptor Post actions inside one Integration Procedure instead of chaining many Post actions directly in the OmniScript.

11. Pass Data: OmniScript → FlexCard

Embed a FlexCard inside an LWC OmniScript using the Custom LWC element.

Prerequisites

  • FlexCard has OmniScript Support enabled
  • OmniScript is LWC-enabled and Activated (required for Custom LWC preview)

Embed Steps

  1. Drag Custom LWC into a Step
  2. Lightning Web Component Name = cf + FlexCard name (e.g. FlexCard AccountCard → cfAccountCard)
  3. Add properties as HTML attributes (kebab-case) with merge-field sources
Property NamePurposeProperty Source Example
record-idPass Id for FlexCard queries%ContextId%
parent-attributePass parent object for merge fields in FCJSON node with object, e.g. %Account%
parent-data + recordsSkip query; map data directly to FC fieldsparent-data = true; records = array/object from OS JSON

parent-data + records Pattern

  1. Custom LWC property parent-data → Source: true
  2. Custom LWC property records → Source: merge field pointing to array in Data JSON
  3. FlexCard parses records and maps nodes to field elements without running a query
Standalone Mode To refresh FlexCard state each time user enters the Step: disable OmniScript Support on FlexCard, then check Standalone Mode on the Custom LWC element.

12. Pass Data: FlexCard → OmniScript

Update OmniScript Action

When a FlexCard is embedded in an OmniScript via Custom LWC, an action on the card can update the parent script's Data JSON.

  1. FlexCard Designer → drag Action element
  2. Action Type = Update OmniScript
  3. Optional Parent Node — target node in OS JSON (e.g. data)
  4. Input Parameters — Key = field/node to update; Value = FlexCard context variable (e.g. {records})
  5. Enable OmniScript Support on FlexCard Setup
  6. Embed FlexCard in OS with Custom LWC (cf prefix)
Example User selects assets on embedded FlexCard → Update OmniScript action passes {records} as Key records → OmniScript Step 2 elements prefill from updated JSON.

Launch OmniScript from FlexCard

  1. Action Type = OmniScript (or Vlocity Action)
  2. Set Type, SubType, Language; pass ContextId via Input Parameters / Attributes

PubSub Between FlexCards

  1. Filter FlexCard: Toggle → Set Values → PubSub Action (Apply button)
  2. Event Type = PubSub; set Channel and Event Name (avoid reserved: reload, updatedatasource, remove)
  3. Product List FlexCard listens on same channel and reloads data

Flyout to Child FlexCard / OmniScript

Flyout Action → set Flyout Type, component, Attributes (e.g. ContextId = {recordId}), optional Data Node for parent data.

14. DataRaptor or Integration Procedure?

Use a single DataRaptor when…Use an Integration Procedure when…
  • Read or write SObjects — not both in one flow
  • Related SObjects (Account ↔ Contact)
  • JSON/XML transform only (no SObjects)
  • Filtering/calc via formulas + mappings is enough
  • Both read and write (≥2 DataRaptors)
  • Unrelated SObjects
  • Conditional multi-step transforms
  • Non-straightforward JSON restructuring
  • Multiple source types (SF, CSV, external, Apex)
  • REST, email, list merge, Try-Catch, loops
Rule of thumb Start with DataRaptor. Move to Integration Procedure when you need orchestration, external calls, or error handling beyond a single mapping step.
