1. What is Vlocity EPC?

Enterprise Product Catalog (EPC) is Vlocity's central place to create, manage, and sell products and services. Think of it as one master catalog that your sales team (CPQ), order team, and billing systems all use together.

Simple analogy EPC is like a restaurant menu that the kitchen, waiters, and cashier all share. When the chef adds a new dish once, everyone sees it — no duplicate menus in different departments.

What EPC contains

  • Commercial catalog — what customers see and buy (offers, prices, bundles)
  • Technical catalog — how products are delivered (services, resources, fulfillment)
Enterprise Architecture — Where EPC Sits
Sales Channels (Web, Store, Call Center) → uses EPC
Vlocity CPQ (Configure, Price, Quote) → reads EPC
Vlocity Order Management → fulfills from EPC
Billing & Backend Systems → receives product data

EPC uses a metadata-driven approach — products are defined once as reusable building blocks, then combined into offers, bundles, and promotions.

2. Business Benefits

Companies in telecom, media, and energy use EPC to launch products faster and at lower cost.

3. Key Solution Features

  • Single catalog — commercial + technical products in one model
  • Reusable components — attributes, picklists, object types shared across products
  • Simple & complex bundles — sell products alone or as packages
  • Flexible pricing — flat, tiered, attribute-based, promotions, adjustments
  • Rules engine — control what customers can buy and at what price
  • Role-based access — product managers, admins, and developers each see what they need
  • TM Forum compliant — follows industry standards (SID model)
  • Versioning & Projects — track changes and release safely

4. TM Forum & SID Model

Vlocity EPC follows the TM Forum Frameworx standard. Products are split into layers — from what marketing sells to what the network delivers.

🛒 Product Offering — What marketing sells (with price)
📋 Product Specification — What the product includes (color, speed, storage)
⚙️ Customer Facing Service (CFS) — Technical service (e.g., broadband internet)
🔧 Resource Facing Service / Physical Resources — Network equipment, IP address, port
Example: Home Internet Package
  • Offer: "Fiber 100 Mbps Plan — $49/month"
  • Product Spec: Router + 100 Mbps speed + SLA
  • Service Spec: Fiber broadband service with authentication
  • Resource Spec: ONT device, IP port, local loop connection

Overrides

Child products inherit attributes from their object type, but you can override values at the product level. You cannot delete inherited attributes — only change their values or picklist defaults.

Example: Download Speed Override Smart Phone object type has Download Speed picklist (25 MB, 50 MB, 100 MB) with default 25 MB. For a premium fiber offer, override the default to 50 MB on that specific product only.

Special Flags (Technical Products)

  • Encrypted — protects PII like SSN or phone numbers
  • Not Assetizable — temporary data (e.g., one-time login password) not stored after order completes

10. Object Types

An object type is a reusable template — like a "class" in programming. Products inherit fields, attributes, and layouts from their object type.

"Is-A" inheritance iPhone is a Smart Phone, which is a Smart Device. Each level adds more specific attributes.
Base Product ← all fields, created once at setup └── Smart Device ← Brand, Size, Storage, Color, OS ├── Smart Phone ← inherits all above └── Smart Wearable ← + Band Type attribute

Layout Management

Layouts control which attributes appear and in what order. In Product Designer, use the General Properties facet with drag-and-drop sections.

Layout Management — Smart Phone Object Type

Drag attributes from the panel → drop into sections

Best practice Define the base object type first. Create child object types only after attributes and layout are ready — children inherit via deep copy.

13. Attribute Rules & Context Rules

Attribute Rules (Configuration Rules)

Control which attribute options appear based on other selections. Each rule has Conditions (when) and Actions (what happens).

Example: Apple Watch Series 5

Condition: Watch Size = 44mm

Action: Exclude "Silver" from Color picklist

Result: If customer picks 44mm watch, silver is not shown as a color option.

Action TypeWhat It Does
ConstrainInclude or exclude picklist values
AssignSet an attribute to a specific value
DisableShow attribute but prevent editing
RequireForce customer to fill in the attribute
HideRemove from UI (still in data)

Context Rules (Qualification Rules)

Control who can see or buy a product. Used for eligibility — e.g., only customers in certain locations see the 5G plan.

Example: 5G Ultra Plan Qualification rule checks customer location. Only eligible customers see the plan in the "Qualified" tab in Vlocity Cart. Others see it as "Disqualified."

1. What is Vlocity CPQ?

Configure, Price, Quote (CPQ) extends Salesforce to help sales teams build the right order — with correct products, prices, and rules — before it goes to fulfillment.

Simple analogy CPQ is like a smart checkout system. It checks stock (availability), your membership (eligibility), whether items work together (compatibility), and calculates the final price — all before you pay.

What CPQ Does

  • Configure products using attributes in the cart
  • Price orders using price lists, promotions, and pricing plans
  • Apply rules so only valid combinations are sold
  • Convert Opportunity → Quote → Order → Asset
  • Support change orders (MACD) on existing customer assets

CPQ Pricing Flow (Runtime)

  1. Availability — Is the product sold in this location? (e.g., fiber not available in rural area)

1. Industries Order Management Overview

Salesforce Industries Order Management (IOM) fulfills orders after CPQ captures them. It breaks commercial products into technical requests and coordinates fulfillment with external systems.

Simple analogy CPQ is placing your order at a restaurant. Order Management is the kitchen — it decomposes the order into cooking tasks, coordinates stations, and delivers the meal.

Two Primary Areas

AreaWhat It Does
Order DecompositionBreaks commercial order lines into technical fulfillment requests (CFS, RFS, resources)
Order OrchestrationSequences and monitors tasks to fulfill those requests via systems and people

After decomposition creates fulfillment requests, orchestration takes over — communicating with billing, provisioning, inventory, and other systems until the order is complete.

3. Orchestration Plan Definitions

An orchestration plan definition groups order processing tasks into a swimlane. At runtime it becomes an orchestration plan instance.

Example: E2E Master Plan
  • Name: E2E Master Plan
  • Show Order: 1 (displays at top of orchestration diagram)
  • Items: Start Order (milestone) → Complete Order (milestone)
  • Scenario: Product = DSL Service, Action = Add

Best Practices

  • Create one main end-to-end plan for major milestones (start → complete)
  • Create separate plans per function: provisioning, billing, logistics, assetization
  • Keep plans simple — avoid loops unless required
  • Create assets as the last auto task before Complete Order milestone

6. Manual Tasks & Manual Queues

Manual tasks pause orchestration until a user completes work (e.g., credit check, manager approval).

Manual queues organize tasks for teams. Users pick tasks from their queue.

Example: Credit Check

  2. Create Manual Task item definition linked to Credit Check OmniScript
  3. Assign queue to the task
  4. At runtime: task appears in queue → agent runs OmniScript → marks complete → orchestration continues

7. Auto Tasks, Systems & Callouts

Auto Task — Create Assets

Runs an Apex class (e.g., Assetizer) to convert fulfilled order lines into customer assets.

Orchestration Systems & Callouts

An orchestration system represents an external system (billing, network, inventory). A callout item sends REST/API requests to that system.

Example: Installation System Callout
  • Create orchestration system: "Training Mocker"
  • Define system interface (URL, credentials)
  • Add Remote Site Settings for the endpoint
  • Create callout item in provisioning plan definition

Fallout Management

When callouts fail, Integration Retry Policies and fallout queues handle retries and manual repair.

8. MACD Orders in Orchestration

Change orders use the same orchestration framework with different scenarios per action:

ActionOrchestration BehaviorExample
AddRun add swimlanes (provision, bill, assetize)New customer adds Spotify add-on
ModifyRun modify swimlanesUpgrade internet speed 40→100 Mbps
DisconnectRun disconnect swimlanes (deprovision, stop billing)Cancel Spotify subscription

Decomposition can be 1:1 (one commercial line → one technical request) or 1:M (one line → many technical requests, e.g., shipping + activation).

9. In-Flight Cancellation & Rollback

In-flight cancellation stops an order mid-fulfillment. PONR (Point of No Return) marks when cancellation is no longer allowed.

  • Rollback Groups — define which completed tasks must be reversed on cancel
  • Smart Freeze — pause running tasks during cancellation processing
  • Staggered Retry Policies — retry failed integrations with increasing delays
PONR Once an orchestration item reaches PONR, the order cannot be cancelled through standard flows — the task must complete or be manually handled.

3. Compatibility Rules — Full Example

Scenario: Office Internet Solution (OIS)
  1. Create 3 product relationships: Requires modem, Excludes home modem, Recommends cloud backup
  2. Create Advanced Rule: "OIS Requires, Excludes & Recommends Rule"
  3. Rule Type: Configuration · Applies to: OrderItem · Active
  4. Add all 3 relationships as Rule Actions (no filters needed)
  5. Test in Cart: Add OIS → modem required message, home modem excluded, cloud backup recommended

4. Entity Filters

Entity filters define conditions that must be true before a rule fires. Two types:

TypePurposeExample
QualificationFilter which line items qualifyAccount in California AND High Priority
EvaluationCheck if ALL/ANY/NONE of items matchNONE of line items = Business Video Service
Example: Exclude Business Video when Download Speed < 100 Mbps
  1. Product Relationship: Business Video Service Excludes Broadband Cable Service
  2. Entity Filter on Download Speed attribute = 25 Mbps; 50 Mbps; 75 Mbps
  3. Advanced Rule combines filter + relationship action
  4. Result: Business Video blocked when speed is below 100 Mbps

Custom Configuration Messages

Add a Message field on product relationships to show friendly text in the cart when a rule fires.

5. Modify Attributes Rules

Change which attribute values customers can pick — based on other products in the cart.

Example: Business Video limits Download Speed
  1. Use Product Configuration Procedures JSON Generator to build action parameters
  2. CONSTRAIN + Exclude: 10 Mbps, 55 Mbps, 100 Mbps from Download Speed
  3. Product Relationship: Business Video → Modify Attributes → Broadband Cable Service
  4. Paste JSON into Action Parameters field
  5. Advanced Rule triggers the relationship
  6. Cart result: only 25 Mbps shown when both products are in cart

6. Reverse Attribute Modifications

When the triggering product is removed, modified attributes don't auto-restore. You need a reverse rule.

Solution pattern
  1. Clone the modify relationship → change exclude to include
  2. Product = Broadband Cable Service (no related product)
  3. Create Evaluation filter: NONE of line items = Business Video Service
  4. Chain evaluation filter inside a Qualification filter
  5. Advanced Rule: when Business Video is gone → restore all Download Speed options

7. Auto-Add Rules

Example: Free phone case for VIP California customers
  1. Product Relationship: iPhone X → Auto-Add → Incipio Case (Min/Max = 1)
  2. Entity Filter: OrderItem where Account Priority = High AND Shipping State = CA
  3. Advanced Rule: Configuration rule with filter + auto-add action
  4. Cart: adding iPhone X for a High-priority CA account automatically adds the case

6. Repricing

Repricing updates prices on existing draft orders, quotes, and assets when price list entries change.

Important: Repricing uses RepricingElementServiceImplementation — it does NOT support attribute-based pricing. Use for standard PLE-based prices only.
Example: Price drop on 4G LTE Data Plan
  • Old PLE: $34.99/mo (effective until yesterday)
  • New PLE: $24.99/mo (effective from today)
  • Existing draft order still shows $34.99
  • Run repricing via VOIInvoker → price updates to $24.99
// Repricing Apex (Developer Console) List<Order> orders = [SELECT Id FROM Order WHERE Id = 'YOUR_ORDER_ID']; Map<String,Object> input = new Map<String,Object>{ 'objectList' => orders }; Map<String,Object> output = new Map<String,Object>(); Map<String,Object> options = new Map<String,Object>(); vlocity_cmt.VOIInvoker.getInstance() .invoke('Repricing', 'repriceLineItems', input, output, options);

7. Pricing Event Hooks (CpqAppHandlerHook)

Event hooks let you inject custom Apex logic into the CPQ pricing process — e.g., adjust price by billing zip code.

  1. Create attribute pricing matrix for zip code → price mapping
  2. Create expression set (AttributePricingProcedure for zip)
  3. Add custom pricing plan step calling GetMatrixPrice
  4. Write Apex hook class implementing hook interface
  5. Register CpqAppHandlerHookImplementation
  6. Add custom column to Cart UI for zip code field
When hooks run: CpqAppHandlerHook is invoked during CPQ API calls — before or after standard pricing logic depending on hook type.

8. Usage Pricing

Usage pricing charges customers based on consumption (e.g., electricity kWh, data GB, gas therms).

  1. Enable usage pricing in CME Admin
  2. Create charge measurements and assign to products
  3. Configure attribute binding for estimated usage quantity
  4. Test in cart — price reflects estimated usage
  5. Combine with attribute-based pricing for tiered usage rates
Example: Energy product Product: Home Electricity Plan · Attribute: Estimated Monthly kWh = 500 · Usage rate: $0.12/kWh → Estimated charge = $60/mo

Key Concepts

  • Attribute Binding — links a product attribute to a usage measurement
  • Charge Measurement — unit of measure for usage (kWh, GB, minutes)
  • Vlocity Object — metadata object for usage configuration
